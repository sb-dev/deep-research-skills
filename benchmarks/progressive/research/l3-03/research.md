## Decision and authority

Keep native bounded retrieval as the eligible baseline. All three engines are conditional implementation candidates, **none is approved for unattended execution, private-data processing or production installation by this static assessment**. The hard criteria are enforceable source restrictions, authorised processors, exact source return, finite aggregate exposure, observable failures and independent output audit. Unknown hard criteria do not pass.

GPT Researcher is the first candidate to prototype for a URL-supplied research adapter after its licence conflict is resolved: it exposes source URLs, a false-by-default complement flag and source-return methods. Open Deep Research is a candidate where a LangGraph adapter is already useful, but the broad research exception path needs a discriminating failure test. STORM is a candidate for staged encyclopedia-style curation with an explicitly chosen retriever; its VectorRM does not implement URL exclusions. These are conditional task-fit inferences, not performance rankings. See eligibility-matrix.md and required-tests.md.

## Revision-bound observations and contrary evidence

- Open Deep Research README's configurable research claim is backed by configuration fields and graph code. The supervisor slices concurrent calls but ends research on any caught exception because the predicate includes `or True`. A partial run could therefore look like normal phase completion to an insufficiently careful adapter; this is a static risk, not an observed failure. [Implementation](https://github.com/langchain-ai/open_deep_research/blob/1b7d2e80db9faa586165c60e09096dbbfd483a64/src/open_deep_research/deep_researcher.py#L290-L342)
- GPT Researcher's supplied-URL branch only performs supplementary web research when `complement_source_urls` is true. This supports an adapter entry point, not a proven network allowlist: redirects, scraper side requests and retrieval variants still need testing. [Research branch](https://github.com/assafelovic/gpt-researcher/blob/6f998577d547b1e54ec662dac63583aa11e3b84b/gpt_researcher/skills/researcher.py#L145-L186)
- STORM writes both research information and article references to JSON and supports separate run phases. However, VectorRM explicitly documents `exclude_urls` as ineffective, whereas YouRM/Bing apply source checks. A blanket “all STORM retrievers enforce exclusions” claim is false at the inspected ref. [VectorRM](https://github.com/stanford-oval/storm/blob/fb951af7744dab086e34962e9bc6fe878e145f83/knowledge_storm/rm.py#L306-L335) [STORM outputs](https://github.com/stanford-oval/storm/blob/fb951af7744dab086e34962e9bc6fe878e145f83/knowledge_storm/storm_wiki/engine.py#L213-L276)

GitHub connector resolved one latest commit per repository, then fetched pinned README and original code/configuration. Full retrieved text and exact URLs are in sources.json; code was statically inspected, not executed.
