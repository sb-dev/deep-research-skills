These releases are cumulative, not separate annual event samples. C4, observed reconciliation: 201,201 provider+ID keys occur in both snapshots; 165,311 have identical canonical full-row hashes and 35,890 have changed fields. There are 7,290 keys only in 202407 and 104,448 only in 202507. No duplicate provider+ID key or blank key was observed within either acquired snapshot. Matching keys are evidence of repeated records, not proof of unique physical items or that every unmatched key is a new event: rekeying or correction may change membership. Snapshot totals must not be added as independent attempts. All counters and input identities are preserved in `observed.json`; `provider-overlap.csv` gives provider breakdowns.

C5, observed mapping changes: despite identical schema/codelist definitions and zero category-ID/label mismatches within either file, 15,364 shared records change category ID/label, and 5,277 change repair status. `category-transitions.csv` records every observed old/new category mapping and its shared-record count; `category-counts.csv` preserves native snapshot categories. For example Fixit Clinic has four retained keys moving from Small kitchen item to Coffee maker. Denmark accounts for 9,783 category changes and 5,261 status changes among 10,280 shared keys. Those changes cannot be treated as new repairs, nor do stable category names prove stable row classification. No causal explanation for the recoding or changed outcomes has been established. No category-adjusted household trend is claimed.

Method/provenance: `calculation.py` checks exact SHA-256 and byte size against `input-manifest.json`, streams all three CSVs with Python csv, accumulates bounded category/provider/status counters, and stores only key/classification/date/canonical-row-digest fields in a disk-backed SQLite database. Batches are 1,000, SQLite cache is capped at 8 MiB and temporary storage is FILE. Joins use provider+ID (the standard's provider-local ID semantics), with ambiguous duplicate keys excluded from overlap analysis should they occur. Full-row digest uses sorted-key JSON over decoded field strings; it is distinct from the raw input SHA-256. No input is altered or de-duplicated for native snapshot counts. Schema equality compares powered resource field and primary-key definitions; codelist identity is established by the same blob in the complete pinned tree, not by assuming that the version label guarantees equality.
