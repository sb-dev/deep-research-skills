## Composition and independence

The three research/curation repositories are alternative orchestrators. Parsers supply representations; a browser captures/interacts with pages; a repository gateway accesses GitHub; DuckDB processes tables; Inspect and Promptfoo execute evaluations. This role partition is an inference from the pinned READMEs and the narrow static claims above, not proof that a complete integrated workflow exists.

Playwright CLI and MCP both declare the same exact playwright/playwright-core version; count them as two interface choices over shared capability. Their separate READMEs and manifests are not independent measurements of browser reliability. The other repositories are distinct projects, but distinct ownership does not establish independent evidence for any common capability claim, and underlying model/data/service dependencies were not exhaustively mapped.

README capability claims not supported by the selected static file remain documentary. In particular, the GROBID build verifies deployment requirements and entry point, not TEI extraction correctness; DuckDB build verifies compiler requirements, not query accuracy; Promptfoo's manifest verifies runtime requirements, not vulnerability coverage. Required adoption tests include parser fixture fidelity, source identity through transformations, browser policy/cancellation, gateway read-only enforcement, database reproducibility, and evaluation task validity.

Top-level licence statements, dependency terms, model weights, input-data rights and hosted-service terms are separate review scopes. This bounded map does not clear any of them or aggregate them into a security score.
