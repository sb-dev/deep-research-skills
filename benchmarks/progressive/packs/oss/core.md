## A08–A09 — Report and recommendation

**Recommendation: retain Open Deep Research as a candidate optional orchestration engine, with native tools remaining the baseline. Do not yet treat its generated report or successful graph completion as an accepted evidence-led research deliverable.** The inspected code supplies useful planning, parallel research, model/tool configuration and writing stages, but the visible failure and transformation paths require an explicit intake and acceptance boundary (C1, C3–C5). This recommendation assumes the receiving skill values auditable sources, bounded operations and visible partial results over unattended report production alone.

Capabilities include optional clarification, model-generated briefs, supervisor-directed research, tool execution, compression, and final writing. Search/provider choices and MCP configuration are exposed, but README claims of broad compatibility remain documentary until actual combinations are tested. The output should be treated as candidate evidence and synthesis requiring source verification, claim mapping, uncertainty treatment and producer/reviewer checks. [Configuration](https://github.com/langchain-ai/open_deep_research/blob/1b7d2e80db9faa586165c60e09096dbbfd483a64/src/open_deep_research/configuration.py), [graph implementation](https://github.com/langchain-ai/open_deep_research/blob/1b7d2e80db9faa586165c60e09096dbbfd483a64/src/open_deep_research/deep_researcher.py) (C1, C5).

Setup is documented around a clone, uv environment/dependencies, an `.env` file and a local LangGraph dev server. For a future evaluation, pin the specified commit rather than assuming the README's unpinned clone command selects it. Python 3.11 matches the checked server config and launch example; `>=3.10` is the broader package declaration. The graph also references an auth module that this corpus does not allow us to inspect. Exact environment variables, authentication requirements, package resolution and startup success remain unverified; no credentials are needed for this static assessment. [Quickstart](https://github.com/langchain-ai/open_deep_research/blob/1b7d2e80db9faa586165c60e09096dbbfd483a64/README.md), [package metadata](https://github.com/langchain-ai/open_deep_research/blob/1b7d2e80db9faa586165c60e09096dbbfd483a64/pyproject.toml), [server configuration](https://github.com/langchain-ai/open_deep_research/blob/1b7d2e80db9faa586165c60e09096dbbfd483a64/langgraph.json) (C2, E11).

The important failure qualification is that an exception inside supervisor research delegation can terminate the subgraph while existing notes continue toward the final writer. The branch contains `or True`, so it is broader than token-limit errors when the classification helper returns normally. Separately, tool exceptions can become text, compression can remove context or return an error string, and final-writing retries can truncate findings. Therefore an adapter must preserve attempted/completed work, errors, source locators, access extent and material transformations, and distinguish partial/failed output from accepted research. These are requirements inferred from the code and core evidence contract; no adapter was built or tested here.
