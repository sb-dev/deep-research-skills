# open-source-ecosystem

Version 0.1.0; core contract 0.1. Assess open-source adoption evidence using revision, licence, code, package, maintenance and actually executed validation as distinct evidence.

Read [method guidance](references/method.md) for the selected investigation. Selection must explicitly name this pack; topic, filename and catalogue presence do not activate it.

Explicit authorised research instructions outrank locked decisions, which outrank this pack, which outranks core defaults. An ambiguous conflict with a locked decision returns to the owner. Evidence truthfulness, permissions, privacy, required review and finite effort remain mandatory. Start with one profile per investigation; multiple profiles need demonstrated compatibility or explicit subscopes.

## Command effects

- **plan**: Set task-fit criteria, pinned revision, allowed repository evidence and execution authority. Observe: Static-only work cannot acquire install/run authority.

- **discover**: Inspect native repository evidence and relevant history/issue samples at declared bounds. Observe: Collection completeness and sampling limits remain explicit.

- **extract-evidence**: Capture source path/ref/locator and evidence kind, including exact setup and licence scope. Observe: README, package declarations and observed execution remain distinct.

- **analyse-evidence**: Reconcile configuration differences and bind code risks to specific missing tests. Observe: A suspicious branch is recorded as a static finding, not a measured failure rate.

- **synthesise**: Present evidence-qualified reuse conditions rather than a universal repository ranking. Observe: Transitive rights, environment and runtime gaps remain visible.

- **refresh**: Compare changed revision/files and only reopen affected claims and validations. Observe: A documentation change does not erase unrelated source checks.

- **audit**: Check revision identity, licence scope, maintenance/sample inference and static-versus-executed wording. Observe: An unexecuted installation cannot pass as operational readiness.

For follow-up-search, resolve the most consequential specialist evidence gap within the existing source and effort boundary. Do not broaden a task merely because a pack has more methods.

An evaluator loads this exact version only for applicable specialist criteria and writes a separate fixed-input review. Core and specialist verdicts remain separate. Preserve historical activation and unaffected findings during correction or deactivation.

## Package boundary

All entry points resolve inside this package. Reject absolute/traversal paths, escaping symlinks, undeclared repository dependencies and load-time execution/network calls. Method URLs are citations. This package has no runtime dependencies or automatic side effects.
