## Comparison contract

One fresh isolated run per condition, same substantive source universe, tool authority, core revision and budget. Both receive the same known baseline leads: the package Python minimum versus selected server/example version, and the broad exception-to-termination path. These facts must not be hidden to favour a pack. No other-condition answer is supplied. The only changed input is explicit pack selection and its method criteria. Parent review gets four additional source actions per pair.

Expected change: Cross-file environment reconciliation and evidence-to-test conditions, including concrete configuration-to-branch boundary analysis that changes the proposed verification, retaining all known baseline cautions.

Require core question fit, source/claim support, temporal and access honesty, preserved evidence and authority. For scholarly specialisation check actual work/report linkage, eligible-version status and design-transfer appraisal. For open-source specialisation check cross-file setup reconciliation, consequential code inspection and static-risk-to-test mapping. Cosmetic differences fail. One pair establishes only the observed application, not a general quality gain.

Status: version 0.1.0 failed to show a material difference. The single affected 0.1.1 rerun passed independent review for concrete configuration-to-branch analysis and discriminating test design. The original failure remains preserved. This is a bounded development observation; installation has not been tested.
