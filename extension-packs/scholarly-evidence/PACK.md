# scholarly-evidence

Version 0.1.0; core contract 0.1. Research a bounded scholarly question with explicit work/report/version units and method-specific appraisal.

Read [method guidance](references/method.md) for the selected investigation. Selection must explicitly name this pack; topic, filename and catalogue presence do not activate it.

Explicit authorised research instructions outrank locked decisions, which outrank this pack, which outranks core defaults. An ambiguous conflict with a locked decision returns to the owner. Evidence truthfulness, permissions, privacy, required review and finite effort remain mandatory. Start with one profile per investigation; multiple profiles need demonstrated compatibility or explicit subscopes.

## Command effects

- **plan**: Specify scholarly units, eligibility and an appropriate appraisal method before retrieval. Observe: Plan states which report/study/version is counted and which inference is authorised.

- **discover**: Resolve relevant scholarly identities and status within the allowed corpus. Observe: Search/selection record differentiates candidate, eligible, unavailable and superseded representation.

- **extract-evidence**: Capture method, task/population, measure, units and locators needed for the finding. Observe: No abstract-only record supplies unseen methods.

- **analyse-evidence**: Link multiple reports and revisions before counting or comparing; appraise threshold transfer. Observe: A revised paper cannot become another independent experiment.

- **synthesise**: Expose design limits and study/report structure; keep implications conditional. Observe: A benchmark threshold is not rendered as universal application acceptance.

- **refresh**: Check the relevant correction/revision and repair affected claims without silently repointing historical evidence. Observe: Unchanged prior findings retain their basis.

- **audit**: Add report-linkage, status-boundary and method-transfer checks to applicable core dimensions. Observe: Bibliographic validity and substantive support receive separate verdicts.

For follow-up-search, resolve the most consequential specialist evidence gap within the existing source and effort boundary. Do not broaden a task merely because a pack has more methods.

An evaluator loads this exact version only for applicable specialist criteria and writes a separate fixed-input review. Core and specialist verdicts remain separate. Preserve historical activation and unaffected findings during correction or deactivation.

## Package boundary

All entry points resolve inside this package. Reject absolute/traversal paths, escaping symlinks, undeclared repository dependencies and load-time execution/network calls. Method URLs are citations. This package has no runtime dependencies or automatic side effects.
