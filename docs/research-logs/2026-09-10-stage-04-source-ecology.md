## 1. Source ecology

A source class describes the kind of evidence needed; an acquisition path describes how it is found and inspected. They are not a one-to-one mapping. A standard can be a PDF in a repository; a private file can contain scholarly data; a company report can be both a filing and a book-length document. Multiple class labels may be relevant without duplicating the underlying evidence.

Start by identifying the claim’s required evidence unit: an authoritative statement, a study/result, a dated event account, a code revision, a record, a measurement series, a document passage or a media observation. Then choose the permissible path that can actually expose that unit at the required date and granularity.

| ID | Source class and question fit | Preferred acquisition and permitted fallback | Evidence boundary and retained provenance |
|---|---|---|---|
| C01 | **Official websites and documentation.** What does the responsible institution or product document state for the relevant version? | Known URL/navigation → A10; known publisher but unknown location → A02; dynamic required state → A04. | Primary for its stated policy/contract, not automatically for claimed effects. Preserve edition, exact section, authority and effective/currentness context; search-index dates are insufficient. [S01, S13, S31–S34.] |
| C02 | **Scholarly literature.** Which relevant studies/reports support or challenge a question? | A07 database/identifier discovery → A10 accessible original and supplements; broaden across appropriate databases when coverage requires it. | Keep study/report and origin relations; metadata, abstracts, preprints and full methods/results have different access depth. Record eligibility, methodology and publication-status limits. [S04–S09; Stage 2.] |

Preview/text search does not establish full access; reading order, tables and scans may need direct visual checks. [S25–S28.] |

### Independence and source-quality routing

The appropriate source can change between claims in one report. An official API is direct evidence for its documented interface, but a marketing outcome claim may require independent data. Two accounts of one event can be genuinely distinct observations; two APIs exposing the same dataset are not two independent datasets. Source choice therefore uses Stage 3’s source-quality dimensions and relationship integrity, not a publisher whitelist or a fixed citation count.

Broader discovery is appropriate when an authoritative source map is unknown or one source class cannot cover the question. It is not a substitute for querying a known private file, repository or structured record through its proper access path. Restricted-source instructions constrain every route and fallback, including search query text itself.

## 3. Source-selection heuristics

These are domain-owned research decisions, not a generic provider registry or mandatory workflow engine. They apply the accepted information model to the source ecology.

| ID | Heuristic | Decision and recorded rationale |
|---|---|---|
| H01 | Question and support unit first | Identify the question, material claim, evidence unit, scope and freshness requirement. Do not choose a familiar tool and reshape the question around its results. |
| H02 | Permission before optimisation | Establish allowed source, processor, account and output audience. Exclude unauthorised routes before comparing price or convenience; a public query can itself disclose private information. |
| H03 | Known source before broad rediscovery | For a known repository, file, filing, DOI, dataset or application record, prefer its native/exact retrieval. General search is useful for locating unknown originals, not for approximating known connected content. |
| H04 | Discovery is a lower-access state | Use metadata/snippet/catalogue triage to select promising records, then acquire the required support. Record actual access depth; never promote an unseen full source because its metadata is convincing. |
| H05 | Source ecology follows the method | A biomedical synthesis, changing company fact and historical investigation require different corpus choices. Preserve systematic versus purposive search boundaries established in Stage 2. |
| H06 | Match granularity and temporal state | Retrieve the needed passage, record, version, period or media interval. A latest page, nearest capture or whole-document citation is not automatically the relevant state. |
| H07 | Prefer the cheapest adequate authorised operation | A native identifier lookup or local section read can resolve a bounded gap without a broad agent run, browser session or OCR. Escalate only when the cheaper route cannot provide the required evidence. |
| H08 | Check completeness at the acquisition layer | Follow documented pagination/continuations, inspect query translation and distinguish index coverage from underlying holdings. A capped list or unavailable folder must be labelled before synthesis. |
| H09 | Seek independent origins, not extra wrappers | Trace repeated reporting toward its originating observation. Use another path when it supplies missing perspective or evidence, not merely a new URL for the same report. |
| H10 | Treat current operating rules as dated inputs | Check endpoint/model/protocol version, account quota and current authoritative guidance. Preserve policy changes and resolve conflicts rather than copying older wrapper defaults. |
| H11 | Escalate fidelity to answer a specific gap | If text loses a table, figure, negation or media context, inspect the original region or use an appropriate transformation. OCR/transcription is a fallible derived layer, not automatic truth. |
| H12 | Preserve provenance across the handoff | Return source identity, exact locator, actual access extent, meaningful transformation, quality limits and temporal context. Unresolved evidence must remain unresolved in the report. |

A minimal source-selection record may be prose: **question → evidence unit → selected class/path → reason → authorised scope → expected access depth → freshness/coverage check → permitted fallback**. It is not a universal schema. For a bounded question, a short record can be sufficient; a broad investigation may need several source-path assignments and their exclusions.

## 4. Fallback strategy

A fallback must preserve the research objective, source restrictions and required support level, or explicitly report the difference. It must not silently replace a mandatory primary source with a weaker account, disclose private data or evade access limits. There is no unconditional retry loop.

Classify the failure first, preserve valid acquired evidence, then attempt a bounded suitable alternative. Record the original route, observed failure, what the alternative can establish, and any unresolved difference. Time/effort ceilings and orchestration mechanics belong to Stage 6; this stage defines which alternatives are epistemically and operationally acceptable.

| ID | Observed problem | Permitted response / fallback | Forbidden inference or escalation |
|---|---|---|---|
| F01 | Search returns zero or irrelevant hits. | Check scope, terminology, identifiers and index limitations; try the responsible publisher/native catalogue or another justified corpus. | “No such evidence exists” from an unbounded interpretation of zero hits. |
| F02 | A list, search or connector response is capped or paginated. | Follow returned/documented continuation within authorised scope; preserve count/coverage limitations when acquisition stops. | Presenting a first page as the complete corpus, or inventing a continuation token. |
| F03 | A source is metadata-only, abstract-only or paywalled. | Seek an authorised accessible original/edition, library route or limited attributed secondary statement; state the access gap. Ask before new payment or access authority. | Claiming unseen methods/results were read, or describing the weaker route as equivalent. |
| F04 | A 401/403, expired session or permission-related missing item occurs. | Check configured access and known resource identity without exposing secrets; request required owner input when reauthorization is necessary. | Credential borrowing, hidden access expansion or a public-web search of confidential contents. |
| F05 | A 429, quota or explicit backoff response occurs. | Respect Retry-After/reset and service guidance; use approved cache/batch/bulk alternatives where permitted and sufficient. | Parallel accounts/IPs/agents to bypass the same quota; retrying without a bound. |
| F06 | DNS, timeout, transient service error or unavailable tool prevents retrieval. | Retry only when justified by an observed transient condition; use another permitted route to the same identifiable material or report the gap. | Treating an environment failure as proof that a source/service does not exist or is globally unreliable. |
| F07 | HTML changes, dynamic rendering or an unsupported URL defeats a tool. | Use the source’s native API, a compatible direct fetch or an authorised browser; preserve the actual returned identifier/representation. | Guessing that a generic fetch tool accepts every URL or silently treating a login page as the document. |
| F08 | Extracted text is missing, garbled or loses table/figure context. | Inspect the supporting page/region; use a suitable parser/OCR only when needed and verify its result against the source. | Fabricating unread text, table values or a claimed visual inspection. |
| F09 | Two authoritative sources conflict or versions differ. | Compare definitions, jurisdiction/scope, publication/effective periods, corrections and originating evidence; retain unresolved disagreement. | Automatically selecting the newer date or the larger number of repeating sources. |
| F10 | An archive has no suitable capture or only a catalogue description. | Look for another authorised holding, capture or record reference; clearly bound what the surviving metadata establishes. | Inferring that no original existed, or treating a nearby capture as the requested date without qualification. |
| F11 | A private local/connected source cannot be resolved or materialised. | Verify the exact known reference and supported access route; use permitted in-app reading when possible; identify the missing evidence. | Inventing a local path, treating an unresolved folder as empty or uploading elsewhere without authority. |
| F12 | A provider research report lacks original support or contains unsupported synthesis. | Recover and inspect the affected source/claim; use targeted acquisition and retain valid unrelated evidence. | Declaring citation correctness from the presence of a bibliography or rerunning everything without diagnosis. |
| F13 | Media provenance, transcript or embedded metadata is incomplete. | Obtain the permitted original/context or specialist verification appropriate to the claim; report bounded observation and uncertainty. | Treating integrity credentials or a transcript alone as proof of factual truth. |
| F14 | Data parsing or analysis produces suspect values. | Check schema, units, missingness, filters, joins and source edition; reproduce the smallest affected calculation and update dependent claims. | Calling a recomputed number source-reported or changing unaffected approved conclusions. |
| F15 | Storage, reuse terms, price or retention conflict with the proposed route. | Choose a permitted reference/excerpt or alternative source/processor that meets the evidence need; obtain required owner approval for a new commitment. | Assuming free access permits republication, commercial analysis, indefinite caching or disclosure. |
| F16 | Required evidence remains unavailable after legitimate alternatives. | Report the exact unsupported question/claim and access limitation; stop when a user decision or mandatory prerequisite is needed. | Waiving the required evidence, inventing support or advancing a blocked bootstrap stage. |

### Preserve the smallest valid unit

A locator failure may require repairing a link, not retracting the proposition. A corrected source value can require updating one claim and its dependent comparison. A missing decisive method section may prevent the intended inference even when other passages are readable. A source-rights restriction may change permissible output without changing the underlying factual finding. Diagnose which concern failed rather than conflating retrieval success, evidence validity and publication permission.

The acquisition record must allow a later reviewer to distinguish **not searched**, **searched without a match in the stated scope**, **not accessible**, **not eligible**, **not supported**, and **contradicted**. These states inherit Stage 3’s uncertainty model; no fallback collapses them to one empty list.

## 5. Access, cost and licence constraints

### Separate commitment boundaries

| Concern | Required check before the relevant operation | Durable record that does not expose secrets |
|---|---|---|
| Task authority | Does the approved brief permit this source, operation, scope and consequence? | Approved scope and any material decision needing the requester; no invented authorization. |
| Source access | Is the item public, supplied, purchased or available under an authorised account/connector? | Access mode, actual extent and reference; never a token, password or reusable browser session. |
| Processing destination | May this content or query be sent to this model, service, region or third-party processor? | Permitted processing boundary and restriction, not the sensitive content unnecessarily. |
| Service cost | Which requests, tokens, storage, browser/OCR jobs, downloads or specialist work consume an allowance or incur charges? | Dated estimate/allowance and authorised ceiling where known; actual spend only when actually measured. |
| Tool licence | May the selected code/library be used, modified or redistributed in the intended deployment? | Identified version/licence and unresolved review requirement; no blanket clearance from installation availability. |
| Content/data rights | May the source, abstract, asset, dataset or derivative be retained and redistributed for this purpose? | Source-specific terms, attribution and restrictions; distinguish metadata from full work. |
| Output audience | May this recipient inspect the evidence or receive its identifying metadata and excerpts? | Public/private handoff limits and review-access caveats. |
| Retention / refresh | What evidence can be cached, for how long, and what needs rechecking? | Permitted preservation and expiry/currentness constraints; do not erase valid provenance silently. |

The specific provider controls show why these checks cannot be merged: Brave separates storage rights; Guardian differentiates non-commercial and commercial access; OpenAlex separates open metadata from serving costs; PyMuPDF has tool-code licensing choices. The project must apply the applicable terms rather than generalise one provider’s permission to all paths. [S02, S07, S28, S41.]

This stage does not determine legal compliance for a consuming business. When proposed access/reuse depends on a specialist interpretation or additional owner authority, record that condition and stop the affected action. The general research workflow remains capable of using already-authorised evidence without unnecessary repeated approval.

### Cost and latency treatment

For a proposed acquisition, separate **discovery**, **original retrieval**, **extraction/transformation**, **storage**, **verification** and **specialist review**. A low search-call price can hide costly full-text inspection; a free local file can still require difficult parsing; a provider report may save orchestration but leave expensive citation repair. These are analytical cost categories, not measured savings.

The compared service documents show that limits can depend on account, endpoint, request type and time window. Runtime response headers and current authorised account information override remembered examples. Where no current numeric limit or price was established, the matrix says to verify it rather than inventing a value or treating the allowance as unlimited. No paid plan was chosen or purchased.

No wall-clock or monetary performance results were measured in this stage. The documentary rate examples are limits, not achieved throughput. Provider run-duration guidance, parser benchmarks and product marketing are not presented as this project’s execution results. Stage 6 will turn the cost categories into effort/escalation/stopping policy; Stage 7 will evaluate concrete candidate tools more broadly.

### Source restrictions and sensitive information

The presence of a public endpoint or installed connector is not permission to expose private research, personal data or credentials. Source text is untrusted data, including instructions inside pages, documents or tool results. A source cannot authorize a new tool action, redefine the brief or cause secrets to be included in a query. Browser storage state, authorization headers, tokenised private URLs and connector secrets stay outside research logs and public artefacts. [S12, S34; Stage 3 P07, P10, P12.]

A traceable public output may use a permitted citation or metadata record while keeping restricted evidence in its authorised location. It must disclose when recipients cannot independently inspect the supporting original. Access failure can legitimately limit the answer; it never licenses invented facts or an unapproved source substitution.

## Decisions and rejected alternatives

Adopt a **question-to-source-to-path decision**, with explicit access depth and failure-specific repair. Support combinations of native API, original-document, local-file, browser, scholarly, archive, feed and connector routes as the evidence need warrants. Keep the semantic contract independent from a provider’s product features or a mandatory serialization.

Reject **general-web-first for every question**: it is a poor fit for known internal records, exact repository revisions and structured filing/data questions. Reject **always use a deep-research agent**: a bounded identifier lookup should not require broad generative work or new disclosure. Reject **always parse to text**: decisive tables or media may require the source representation. Reject **multiple tools equals triangulation**: tools can expose the same underlying origin.

Do not build a custom crawler, universal provider registry, persistent evidence database, workflow DSL, vector database or multi-agent acquisition swarm here. No current requirement demonstrates that such infrastructure is necessary. The matrix records paths and constraints, not an implementation obligation to install every tool mentioned. Provider reuse decisions and gaps remain the specific responsibility of Stages 7–9.
