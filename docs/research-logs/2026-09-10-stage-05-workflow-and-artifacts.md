## 1. Workflow map

### Derivation and alternatives

Stage 2 distinguishes comprehensive, purposive, bounded-verification and interpretative work. Therefore a credible common workflow must preserve responsibilities without requiring every question to become a systematic review. Stage 3 requires claim-to-evidence traceability and distinct support, review and temporal semantics. Stage 4 requires a source path appropriate to the evidence unit, with actual access depth and permission preserved. The following design joins those requirements; it does not derive research practice from a provider's interface.

| Alternative | Advantage | Defect against the inputs | Decision |
|---|---|---|---|
| One search followed by a report | Few visible operations. | Loses selection, source dependence, extraction, uncertainty and support auditing. | Reject as the workflow; a bounded answer can still have compact records. |
| Mandatory comprehensive review for every question | Explicit protocol and corpus traceability. | Forces unnecessary retrieval and falsely universalises one tradition. | Reject as default; permit the method when the brief actually requires it. |
| Separate skill and file for every candidate arrow | Highly visible decomposition. | Confuses logical responsibility with installation/runtime architecture and duplicates authoritative values. | Reject the packaging assumption. |
| Eight responsibility groups with explicit evidence, review and repair boundaries | Covers the whole candidate flow while permitting small and specialised work. | Requires explicit branch and record-update semantics, supplied below. | Adopt. |

The operations are a domain map, not a workflow DSL, lifecycle engine, required agent team or mandatory eight-command API.

```text
W01 Frame and authorise the brief
  → W02 Plan method, source strategy and evidence needs
  → W03 Discover and triage candidate sources
  → W04 Acquire, extract and establish relevant identity/origin
  → W05 Map claims, contradictions, alternatives and gaps
       ↔ W06 Resolve a bounded gap using the appropriate earlier operation
  → W07 Synthesise and audit the exact proposed deliverable
  → W08 Deliver the reviewed revision with limitations and handoff

A required user decision blocks progression.
A defect re-enters its owning operation, not automatically W01.
A refresh starts from the last verified deliverable and its changed context.
```

### Proportionate paths through the map

A bounded factual check may combine W01–W02 in two clear sentences, locate one known source, extract a short supporting passage, test the exact claim, record the scope of the contrary check and issue a small reviewed answer. It need not generate empty folders, a long protocol or a multi-source quota.

A comparative investigation keeps explicit criteria, independent-origin analysis and evidence differences. A formal evidence review needs its specialist search and appraisal method, not just the same eight labels. Contested or interpretative work preserves alternative explanations; a signed-off report can honestly conclude that a question remains unresolved. The chosen form must not claim stronger coverage or professional assurance than actually performed. [Stage 2 M1–M9; Stage 3 sections 1 and 4; Stage 4, Source-selection heuristics.]

## 2. Artifact architecture

The companion [artifact contracts](2026-09-10-stage-05-artifact-contracts.md) defines A01–A11, each with all eight required concerns. These are logical responsibilities, not a compulsory eleven-file scaffold.

**Compact form:** one consumer-owned `research.md` with clearly identifiable brief, plan/search record, sources, evidence, claims, analysis, report and review sections. Contradictions, gaps and transformation records may be small named subsections. A statement that no relevant contradictions were found must specify the inspected scope; unsearched is not equivalent to none.

**Expanded form:** split the same records when separate updates, volume, restricted access or reviewer ownership make that useful. The following is a consumer research-run layout, not production surfaces to create in this bootstrap repository:

```text
research/<run>/
  brief.md                         A01
  plan.md                          A02, including search/selection record
  sources/source-register.*        A03
  evidence/evidence-register.*     A04
  claim-source-matrix.*            A05
  analysis.md                      A06 contradictions, A07 gaps, A08 synthesis
  report.md                        A09, issued view with version and limits
  provenance.*                     A10, only if separate transformations warrant it
  evaluation/review.md             A11
```

Rows/sections are legitimate records. CSV, JSON or Markdown can be selected for the work; no universal schema is imposed. A02 references A03 selections rather than maintaining a competing list. A05 is the authoritative claim/support record; a matrix rendered from another chosen structured claim record is a view, not a second authority. A08 references claims; A09 renders them. A10 owns transformation context, not duplicates of every source field. An empty contradiction or gap file is never needed merely to match a diagram.

When splitting a compact note, preserve record IDs, locators, meaning, restrictions and review revision. Record the relocation and repair all referring links. A move without semantic change does not invalidate the evidence, but consumers must still resolve its new locator. If the split changes wording or removes context, it is a substantive revision requiring the corresponding recheck.

An issued artifact is not overwritten without revision history. Use the consumer project's existing version control or explicit versioned filenames; no Git dependency is imposed on every user. A file digest is useful for verifying unchanged bytes, not proof of truth. Retention is subject to authorised source rights and privacy. When required deletion removes support, keep only permitted metadata and disclose the resulting audit limitation; preservation does not authorise retaining prohibited content.

## 3. State and decision semantics

### Keep unlike states separate

| Concern | Values / meaning | Invalid conflation |
|---|---|---|
| Research activity | active; blocked; ready-for-review; needs-repair; delivered. A withdrawn deliverable can still have an active correction. | A completed tool call does not mean research is complete or the report was delivered. |
| Brief authority | proposed; authorised for the stated scope; reopened for an identified decision. | An installed tool or selected pack does not authorise its use on private data. |
| Source selection and access | included/excluded/undecided and the actual access extent are separate fields. | Excluded, inaccessible, no match and disproved are not synonyms. |
| Claim support | supported; qualified; contested; unsupported; unassessed, preserving Stage 3 definitions. | A checked or popular claim is not automatically supported. |
| Review | unchecked; checked; needs-recheck, tied to exact content and method. | Prior review cannot cover a changed claim, input or necessary assumption silently. |
| Deliverable revision | draft; issued; superseded; withdrawn, with identity and change reason. | Superseded does not mean every historical claim was false. |
| Delivery result | not attempted; attempted-unverified; confirmed; failed with observed reason. | A timeout after a write does not establish that the destination was unchanged. |

These terms define information needed at decisions, not an implementation requirement for a state-machine library. A single note can express them plainly. Confidence remains an explanation, not a state or pass/fail score.

### Gates and decisions

G01 authorises acquisition only when the next action is within an unambiguous brief, source/processor scope and known commitment limits. G02 permits synthesis only when the required questions have mapped support or explicitly recorded limitations, and no unresolved prerequisite forbids the intended deliverable. G03 permits issue only after applicable review of the exact report, support closure, truthful coverage/currentness and audience checks. G04 permits confirmed-delivery status only when destination evidence supports it. G05 permits a refresh or repair to be closed only after dependent claims and review records have been updated and unaffected work preserved.

An unanswered mandatory question does not automatically forbid every report: an authorised investigation can conclude that the answer cannot be established. It does forbid claiming that the question was answered or that the originally requested actionable conclusion is supported. If the brief explicitly requires a definitive result or a specific approval, proposing a limitations-only substitute needs the requester's decision. An unresolved bootstrap prerequisite always blocks the next bootstrap stage; the research limitations outcome cannot waive the execution instructions.

A consequential decision record contains the target and revision, decision type, authorised owner, outcome, reasoning/support, applicable date and affected downstream work. Relevant types are scope/method commitment, source/processor permission, expense approval, acceptance of explicitly limited output, reopening an approved decision and external issue/withdrawal. Routine triage and claim appraisal are recorded research judgements, not requests for repeated user approval. The requester's original instruction can be the permission record when sufficiently specific.

### Editing, interruption and resumption

Before modifying an artifact, read its actual current revision. Write new source/evidence records before updating dependent claim links. Verify reference closure and the changed review scope before marking the new version ready. If a write can fail midway, retain the last accepted coherent version and a draft change record; do not present partially updated material as an issued package. One designated writer reconciles competing edits to a record; conflicting updates require inspection and reconciliation, not last-write-wins by accident. This is a document discipline, not a distributed workflow platform.

After interruption, read the brief, actual current artifacts, review record and delivery destination. Separate what was planned, attempted, committed and verified. Reconstruct the smallest pending operation from durable evidence. Before repeating any consequential action whose result was lost, inspect the target for an already-created result. Preserve valid source retrievals and reviews; restart only the missing or invalidated responsibility. If the actual state cannot be verified and the next action needs that state, block and request the required input rather than inventing failure or success.

The Stage 4 recovery is an observed example of this distinction: the remote stage commit existed while the progress record still said publication verification was pending. Checking the remote commit/tree resolved the pending gate without redoing the research. This stage generalises only that observed recovery behaviour; it does not claim a tested universal exactly-once delivery system.

| H02 | Planner/researcher → acquisition executor | Question/evidence unit; selected path and source scope; expected representation/locator; allowed processor; bounded action; permitted fallback. ## 5. Repair routes

First classify the defective unit, then follow only its material dependencies. Dependent means that changing this input could change the claim, qualification, comparison, review judgement or permitted use. References can be followed through ordinary records; a maintained universal graph is not required. Where dependency coverage is uncertain, explicitly expand the review boundary rather than falsely claiming a perfectly isolated repair.

| ID | Defect and owner | Smallest correction / preserved work | Re-entry and required recheck |
|---|---|---|---|
| F01 | Wrong question, scope or intended use; A01 | Reopen the affected brief decision with its owner. Retain sources that are still applicable, not invalid conclusions. | W01→W02; recheck all findings dependent on the changed need. |
| F02 | Search coverage or eligibility error; A02/A03 | Repair the missing search/criterion and affected selections; preserve valid acquired evidence. | W02/W03→W05; recheck completeness and dependent synthesis. |
| F03 | Inaccessible original or incomplete response; A03 | Correct access state, follow a permitted source-specific fallback, or retain an explicit gap. | W03/W04; verify real extent before relying on new content. |
| F04 | Mis-extraction, lost context, OCR/table/data error; A04/A10 | Correct the smallest passage, value, region or transformation. Preserve originals and unrelated extractions. | W04→W05→W07; recheck the claim and rendered qualification. |
| F05 | False duplicate merge or false independence; A03/A04/A05 | Correct identity/origin relation and only affected counts or confidence. Keep distinct observations when justified. | W04/W05; recheck aggregation, contrary coverage and synthesis. |
| F06 | Unsupported inference or hidden assumption; A05/A08 | Split/narrow/withdraw the proposition or acquire the specific missing support. Do not rewrite source statements. | W05/W06→W07; check premises, alternatives and final wording. |
| F07 | Concealed contradiction/null result; A06/A05 | Restore eligible opposing evidence and its effect; separate scope/time differences from genuine conflict. | W05→W07; uncertainty and fitness-for-use review. |
| F08 | Stale currentness or future-effective claim; A03/A05/A09 | Recheck only the changing basis; preserve still-valid historical claims and actual access dates. | W04/W05→W07; verify the stated valid-as-of basis. |
| F09 | Citation misplaced, broken locator or rendering loss; A09 or A03 | Fix the locator/view if underlying support is unchanged; otherwise reopen the affected support chain. | W07, or W04/W05 when source identity/support changed; no automatic full research rerun. |
| F10 | Missing or invalidated review; A11 | Perform the required review against actual revisions; retain review of demonstrably unaffected records. | W07; unresolved mandatory review blocks issue. |
| F11 | Unauthorised disclosure/retention; all affected records | Stop the action, protect/remove material as required by the authorised policy, record only permitted provenance and the audit consequence. | Block for owner input where needed; recheck audience/access before W08. |
| F12 | Interrupted/uncertain delivery; A09/A11 | Read destination state and recover a receipt before retrying. Preserve the issued revision; do not declare duplicate work necessary from a timeout alone. | W08; verify the actual target/result. |
| F13 | New evidence or changed research context; A01/A03–A09 | Identify affected questions/claims and justify a refresh; distinguish new evidence from correction of an old error. | Reconfirm W01 context, then smallest W02–W07 route; reissue only after G05. |

A correction to an issued report produces a visible revision and a handoff under H06 when authorised. A severe unsupported conclusion may require withdrawal; continued availability of unrelated valid evidence is not a reason to leave the defective claim presented as sound. Conversely, a broken citation locator alone does not prove the proposition false.

## Worked execution reviews

These are design walkthroughs, not live installed-skill runs. They test whether the contracts determine the next action and preserved records without inventing missing workflow rules. Machine-readable [contract cases](2026-09-10-stage-05-contract-cases.json) support additional gate and repair checks.

**Bounded answer.** W01–W02 define one exact document question, an official-source restriction, current inspection requirement and a short attributed answer. W03 resolves the known source rather than scanning the whole web. W04 records S1 and E1 at a precise passage; W05 produces C1 with limited attribution and no claim of independent corroboration. W06 is not invoked when no material gap remains. W07 checks the exact answer and source, records review revision, and W08 issues the same reviewed text with its as-of scope. A single note can contain all necessary records; no empty contradictions/provenance files are created.

**Contested comparison.** W01 fixes criteria and use. W02 selects complementary evidence classes. W03–W04 acquire two independent origins and a repeated secondary account, retaining its shared origin rather than counting three observations. W05 distinguishes disagreement about definitions from actual opposing results. W06 targets one missing denominator; failure preserves the gap. W07 either reports a qualified comparison with the consequential uncertainty when authorised, or blocks if the requested decision requires the unavailable fact. It cannot simply select the majority or hide the gap in an appendix. W08 hands the supported scope to the decision owner, not an automatic purchase/deployment instruction.

**Incremental correction.** An issued report uses E1→C1 and E2→C2. A correction to the extraction changes E1. The researcher retains the earlier source/evidence version, records E1's replacement, marks C1 and its dependent synthesis/review as needing recheck, and preserves the E2/C2 chain. W04–W07 verify the corrected value and dependent wording; H06 explains the revision. C2 is not needlessly reacquired or reworded. If a shared denominator also affects C2, the dependency review expands: preservation never excludes genuinely affected work.

**Interrupted handoff.** A publish call returns no readable receipt. A09 stays issued or ready as evidenced locally, but delivery is attempted-unverified. W08 queries the destination. If the intended revision exists, its identity/result becomes the receipt and no duplicate publication is made; if absent with a conclusive permitted check, a retry may be appropriate. If ambiguous, the process blocks the consequential retry. This matches the observed Stage 4 recovery without promising a universal transactional tool interface.
