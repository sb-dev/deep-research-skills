# L3-03 — Optional research-engine adoption

[All research examples](../../README.md#learn-by-researching)

## Problem

Use the `open-source-ecosystem` profile to distinguish documentary capability, static inspection and tests still required.

## Exact prompt

Run this prompt in a consumer project with the skill selection it names.

```text
Use installed deep-research and research-evaluate with open-source-ecosystem explicitly selected; record its actual revision and report if it is unavailable. Assess Open Deep Research, GPT Researcher and STORM as optional execution engines beneath evidence-led research skills. Begin with langchain-ai/open_deep_research, assafelovic/gpt-researcher and stanford-oval/storm on GitHub. Pin inspected code/configuration states. Compare source control, source/citation return, private/local-processing boundaries, bounded work, interruption/failure visibility, integration burden and required output audit. Inspect original code/configuration where a README claim is consequential. Separate top-level code licensing from dependency, model, data and service terms; no professional legal clearance is implied. Stars and update dates do not establish suitability.

Produce an eligibility-based recommendation and explicit installation/failure tests still required. Do not claim runtime performance, installation or API expenditure unless actually authorised and executed. Allow at most 12 searches and 36 source reads/actions, with separate review reserved; no new paid runs, purchases or credentials.

Write research/l3-03/research.md, eligibility-matrix.md, required-tests.md and evaluation/audit.md beneath research/l3-03/. Keep material claims linked to exact original passages or code fields and distinguish static observations from executed tests. Preserve uncertainty, contrary evidence and prior valid revisions. Return actual paths, eligibility findings and outstanding tests rather than an unmeasured readiness certificate.
```

## Expected artefacts

## Evaluation contract

Evaluate pack effects, documentary versus runtime evidence and provider boundaries.

Static observations versus actual installation readiness; AU01/FX10, PD02. Explicit open-source-ecosystem.

Review the actual source access, evidence and claim support, temporal scope, uncertainty, resource bounds and preservation required by the prompt. Distinguish producer self-checks from fixed-input independent evaluation. A passing structural check does not establish research quality.
